# Sharaga Info Bot

Telegram-бот, который отвечает по Obsidian-хранилищу
[Sharaga](https://github.com/TeamKait/KAIT20-INFO): почта преподавателя, что он ведёт,
информация по предмету, любая заметка целиком.

Без LLM и без записи в vault: бот только читает свою git-копию и ищет по ней.

## Команды

| Команда | Что делает |
|---|---|
| `/teacher` | список всех преподавателей |
| `/teacher Иванов` | заметка преподавателя: фото, почта, предметы |
| `/teacher Иванов email` | только почта |
| `/teacher Иванов предметы` | какие предметы ведёт |
| `/subject` | список всех предметов |
| `/subject МДК.11.01` | кто ведёт, оценки, посещаемость, ИУП, аттестация |
| `/find аттестация` | найти заметку целиком (по названию или тексту) |
| `/sync` | обновить данные из GitHub вручную |
| `/start` | справка |

Имена понимаются неполно и с опечатками: `Медведев`, `медведев в с`, `Кузнецов`
находят нужного человека. Почта с пометкой «не подтверждена» сопровождается
предупреждением.

В карточках есть inline-кнопки: из предмета — «Карточка преподавателя», из
преподавателя — отдельная кнопка на каждый его предмет (кнопки идут вертикально).

Markdown из заметок рендерится нативно через **Rich Messages** (Bot API 10.1+):
заголовки, списки, цитаты, ссылки и таблицы с рамками. В `/teacher` и `/subject`
первая строка — крупный заголовок с ФИО или названием из имени файла. Заметка
отправляется в исходном виде — бот не добавляет свой тип и ссылку на GitHub; он
лишь адаптирует Obsidian-синтаксис (`[[...]]`, callout’ы, вложения). Фото
преподавателя подтягивается из `Прочее/Картинки` и встраивается в сообщение.
Если Rich Messages недоступны, используется HTML-фолбэк, где таблицы выводятся
моноширинным блоком.

## Как это работает

1. При старте бот клонирует репозиторий vault в `/data/vault` (чистый Go, git в
   контейнере не нужен) и строит индекс в памяти.
2. Раз в час (или по `/sync`) делает `git fetch` и жёстко сбрасывает рабочую
   копию на `origin/<ветка>` — конфликтов не бывает, потому что бот никогда не
   пишет в vault.
3. Заметки разбираются по шаблонам: `Преподаватели/<ФИО>.md` → почта, пометка
   «Не подтверждено», `[[предметы]]`; `Предметы/<название>.md` → `Кто ведёт` и
   секции.
4. Поиск нечёткий: нормализация регистра и `ё`, префиксы, инициалы, расстояние
   Левенштейна. Для 10–1000 заметок этого достаточно, поисковый движок не нужен.
5. Сообщения, отправленные до запуска бота, не обрабатываются: при старте
   запрашивается последний `update_id`, и поллинг начинается со следующего.

## Быстрый старт (VPS + Docker)

### 1. Токен

В Telegram: [@BotFather](https://t.me/BotFather) → `/newbot` → скопировать токен.

### 2. Privacy mode

В группе бот по умолчанию видит только команды, адресованные ему
(`/teacher@bot`). Чтобы работали и обычные `/teacher`, отключите privacy mode:

`/setprivacy` → выбрать бота → `Disable`

После смены настройки **удалите и заново добавьте бота в группу** — иначе
Telegram не применит её.

### 3. Запуск

```bash
git clone <repo-url> sharaga-bot
cd sharaga-bot
cp .env.example .env
nano .env            # вставьте TELEGRAM_BOT_TOKEN
docker compose up -d --build
docker compose logs -f
```

Добавьте бота в группу и отправьте `/start`.

## Локальный запуск

Нужен Go 1.27+.

```bash
cp .env.example .env
# укажите токен и локальную папку для клона:
# VAULT_DIR=./.vault
go run ./cmd/bot
```

На Windows путь по умолчанию `/data/vault` недоступен — задайте `VAULT_DIR` явно.

## Конфигурация

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — | токен от BotFather, обязателен |
| `VAULT_REPO_URL` | `https://github.com/TeamKait/KAIT20-INFO.git` | репозиторий хранилища |
| `VAULT_BRANCH` | `master` | ветка |
| `VAULT_DIR` | `/data/vault` | куда клонировать |
| `IMAGES_DIR` | `Прочее/Картинки` | папка с картинками внутри vault |
| `GIT_TOKEN` | — | PAT для приватного репозитория |
| `SYNC_INTERVAL` | `1h` | период обновления (минимум `1m`) |
| `ALLOWED_CHAT_IDS` | — | chat id через запятую; пусто — любой чат |
| `LOG_LEVEL` | `info` | `debug`, `info`, `warn`, `error` |
| `TELEGRAM_API_URL` | `https://api.telegram.org` | локальный Bot API |

`.env` подхватывается и локально, и в Docker (`env_file`). Токен в образ не
попадает.

## Данные

- Клон живёт в named volume `vault-data` → `/data`. При пересоздании контейнера
  ничего не теряется.
- Бот read-only: `git fetch` + `reset --hard` только в свою копию, исходные
  заметки не меняются.
- Если GitHub недоступен, бот продолжает работать на последнем клоне (в логах
  предупреждение).
- `/sync` — принудительное обновление, полезно сразу после правки заметок.

## Приватный репозиторий

Создайте fine-grained PAT с доступом `Contents: Read` и укажите `GIT_TOKEN`.
Для публичного репозитория переменная не нужна.

## Разработка

```bash
go test ./...
RUN_GIT_TEST=1 go test ./internal/vault -run TestSyncClone -v
VAULT_TEST_DIR=/path/to/vault go test ./internal/vault -run RealVault -v
```

Структура:

```
cmd/bot            — точка входа, фоновая синхронизация
internal/config    — env-конфиг
internal/vault     — git-синхронизация, парсинг Markdown, индекс
internal/search    — нормализация, нечёткое сравнение, ранжирование
internal/bot       — Telegram-хендлеры, форматирование, guard
```

## Ограничения

- Ожидается структура заметок из шаблонов `Преподаватели`/`Предметы`. Новые поля
  добавляются в парсер.
- `/find` ищет по названию и тексту, но не отвечает на произвольные вопросы —
  LLM сознательно не используется.
- Длинные заметки в `/find` отправляются файлом `.md`, карточки — несколькими
  сообщениями.

## Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| `401 Unauthorized` | неверный `TELEGRAM_BOT_TOKEN` |
| Бот молчит в группе | privacy mode включён: `/setprivacy` → `Disable`, затем удалить и заново добавить бота |
| `permission denied` для `/data/vault` | том создан старым контейнером: `docker compose down -v` (клон пересоздастся) |
| «Не нашёл преподавателя» на верном имени | проверьте `VAULT_BRANCH` и выполните `/sync`, затем `docker compose logs` |
| Пустой список после старта | репозиторий недоступен и локального клона нет — смотрите лог `initial git sync failed` |

Обновление бота:

```bash
git pull
docker compose up -d --build
```
